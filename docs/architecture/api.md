# API architecture

The API is a NestJS modular monolith run locally with Fastify and packaged in
a Worker that forwards requests to a Cloudflare Container in production.

## Módulo

```text
apps/api/src/modules/<owner>/
├── domain/
├── application/
├── infrastructure/
├── presentation/
└── public/
```

The layers have different responsibilities:

- `domain`: concepts, invariants, business rules, and owner-specific
  capabilities;
- `application`: commands, queries, input/output DTOs, contextual
  authorization policies, and use-case orchestration;
- `infrastructure`: Drizzle, repositories, mappers, and external
  integrations;
- `presentation`: controllers, HTTP DTOs, decorators, pipes, and filters;
- `public`: stable contracts used by other modules;
- `app`: bootstrap, global composition, configuration, HTTP security, and
  cross-cutting runtime;
- `shared`: kernel and technical infrastructure without product ownership.

## Fluxo

```text
HTTP
 ↓
presentation
 ↓
application
 ↓
domain + ports
 ↓
infrastructure
```

The controller adapts the transport. The use case coordinates the operation.
The domain decides its own rules. Infrastructure implements ports and accesses
PostgreSQL, Redis, R2, email, or external providers.

Rules must not be duplicated across layers without a reason. A contextual
authorization decision belongs to the application; a business rule belongs to
the domain.

## Dependencies

- a module may use its own internals;
- a module may use another module only through its `public` folder;
- `shared` does not import product modules;
- repositories are not public contracts;
- Drizzle schemas remain in the shared physical catalog and do not define
  behavioral ownership;
- the HTTP contract is derived from controllers and DTOs documented by
  Swagger.

## Contract and validation

OpenAPI is generated by the real NestJS application and published to
`packages/api-contract`. The Web consumes this contract through
`openapi-fetch`. HTTP DTOs are classes with validation and Swagger decorators;
use-case DTOs represent application inputs and outputs.

## Current verification

- domain: unit tests;
- use cases, services, and policies: unit tests;
- authentication: dedicated integration tests;
- contract: OpenAPI generation and validation;
- build: TypeScript, without Webpack.
